## Findings (priorisiert)

### MUST FIX (merge blocker)
- **[SEC] CSP vs. Realität (Inline/Dynamic Styles + Inline Script)** — `backend/web/main.py:291@b098d1d`
  - Problem: Prod‑CSP setzt `style-src 'self'` (kein `unsafe-inline`). Gleichzeitig existieren:
    - Inline `<script>` im SSR‑HTML (`backend/web/main.py:4627@b098d1d`) → wird von `script-src 'self'` in Prod blockiert.
    - Dynamische Style‑Mutationen in JS (`backend/web/static/js/gustav.js:846@b098d1d`, `backend/web/static/js/gustav.js:1203@b098d1d`) → riskant unter `style-src 'self'` (Browser blocken Inline‑Styles).
    - Dritt‑JS (HTMX) injiziert per Default ein `<style>`‑Tag (`backend/web/static/js/vendor/htmx.min.js:1@b098d1d`) → CSP‑Violation in Prod.
  - Impact: Prod‑UI kann brechen (Modals/Tooltips/Layout), außerdem CSP‑Violations “spammen” Logs/Console.

- **[SEC] H5P `/ajax` ist nicht konsistent “same‑origin + no‑store”** — `h5p-service/server.mjs:1261@b098d1d`
  - Problem: `/ajax` ist `POST` und wird von Webcomponents genutzt (Browser). Aktuell:
    - same‑origin wird nur für eine Teilmenge von `action`‑Werten erzwungen (writeActions).
    - Antworten nutzen nicht `sendJson` → `Cache-Control: no-store` fehlt (und `Vary: Origin` ist nicht garantiert).
  - Impact: unnötige CSRF‑/State‑Manipulation‑Surface (z. B. student user data), plus Caching‑Risiko für sensitive Antworten.

### SHOULD FIX (wichtig, aber ggf. Post‑Merge)
- **[SEC] CSRF‑Diag‑Log kann Referer‑Pfad/Query loggen** — `backend/web/routes/learning.py:802@b098d1d`
  - Risiko: PII/Token‑Leaks in Logs/Dateien (`CSRF_DIAG_LOG`).
  - Fix‑Richtung: nur Origin (scheme+host) loggen, keine Pfade/Queries.

- **[SEC] H5P Export: `Content-Disposition` nutzt unsanitized `contentId`** — `h5p-service/server.mjs:1256@b098d1d`
  - Problem: `filename=${contentId}.h5p` wird direkt in einen Header interpoliert.
  - Impact: Header‑Injection/Response‑Splitting (wenn `contentId` jemals nicht strikt numerisch ist).
  - Fix‑Richtung (KISS): `contentId` allowlisten (z. B. `^[0-9]+$`), sonst 400; und Header‑Value sicher quoten.

- **[SEC] H5P finishedData: Upstream‑Response‑Body wird geloggt** — `h5p-service/server.mjs:1419@b098d1d`
  - Problem: bei Fehlern wird `await r.text()` in Logs geschrieben.
  - Impact: potenziell sensitive Metadaten/IDs in Container‑Logs (DSGVO‑Risiko).
  - Fix‑Richtung: logge nur Status + errorId (oder eine kurze Klassifikation), niemals Bodies.

- **[SEC] H5P Service läuft als root** — `h5p-service/Dockerfile:1@b098d1d`
  - Risiko: größerer Blast Radius bei RCE/Path‑Traversal in Third‑Party (H5P Pakete = “trusted content”, aber trotzdem).
  - Fix‑Richtung: non‑root user + passende Ownership für `/data/h5p`.

- **[ROBUSTNESS] Student‑Visibility Check kann false‑deny bei großen Kursen** — `h5p-service/server.mjs:333@b098d1d`
  - Problem: `fetchAllowedH5PContentIdsForCourse(...limit=100...)` kann bei >100 Aufgaben/Abschnitten H5P‑IDs “abschneiden”.
  - Impact: Schüler bekommen 403 “forbidden”, obwohl Content released ist.
  - Fix‑Richtung:
    - **Option A (minimal, ohne API‑Änderung):** pagination/loop in `h5p-service` (offset += limit) bis keine weiteren Sections kommen.
    - **Option B (empfohlen, contract‑first, Datenminimierung):** dedizierter Learning‑Endpoint als **Access‑Check** pro `content_id`.
      - Why: Kein Pagination‑Risiko, kein “Enumeration‑Leak” (Student sieht nicht alle IDs), minimaler Payload, einfache DB‑Query.
      - Vorschlag: `GET /api/learning/courses/{course_id}/h5p/contents/{content_id}/access`
        - `204` = allowed (released H5P task exists for student in this course)
        - `404` = not allowed / not released / not member / course unknown (fail‑closed, leak‑minimizing)
        - `403` = caller not student
        - `400` = invalid_uuid (course_id) / invalid_content_id (format)
      - H5P‑Service kann optional kurz cachen (TTL) pro `(session_id, course_id, content_id)` um Burst‑Loads abzufangen.

- **[ROBUSTNESS] Default Upload‑Limit 512MB** — `h5p-service/server.mjs:44@b098d1d`
  - Risiko: Disk‑DoS (lokal/prod identisch).
  - Fix‑Richtung: `H5P_MAX_UPLOAD_BYTES` in `docker-compose.yml` setzen (MVP‑Grenze).

- **[ROBUSTNESS] Auth‑Caches sind unbounded** — `h5p-service/server.mjs:63@b098d1d`
  - Problem: `authCache` und `courseH5PAuthCache` wachsen mit Sessions/Course‑IDs.
  - Impact: Memory‑Leak über Laufzeit (Sidecar lange up).
  - Fix‑Richtung: max‑size + einfache Eviction (LRU) oder periodisches Cleanup (TTL‑Sweep).

### NICE TO HAVE
- **[DOC] Vendor‑Assets Lizenz‑Hinweis** — `h5p-service/vendor/h5p/core/LICENSE.txt:1@b098d1d`
  - Fix‑Richtung: kurze Doku/Notice, welche Third‑Party‑Assets shipped werden (FOSS‑Transparenz).

- **[CONSISTENCY] Cache‑Header H5P Service vs. OpenAPI** — `h5p-service/server.mjs:156@b098d1d`
  - Problem: Runtime nutzt `Cache-Control: no-store`, OpenAPI dokumentiert meist `private, no-store`.
  - Fix‑Richtung: entweder Runtime auf `private, no-store` ziehen (empfohlen) oder Vertrag anpassen.

- **[DOC/CONSISTENCY] Vendor‑Drop Hygiene (Maps/Update‑Pfad)** — `h5p-service/vendor/h5p/editor/ckeditor/ckeditor.js.map:1@b098d1d`
  - Problem: sehr große Sourcemaps/Assets erschweren Review/Repo‑Size.
  - Fix‑Richtung: dokumentiere Update‑Prozess + Lizenzquelle; prüfe, ob `.map` in Prod nötig ist.
## Entscheidungen (benötigt/empfohlen)
1) **CSP‑Strategie (empfohlen für Merge‑Fix):**
   - `script-src`: **immer** strikt (`'self'`, kein `unsafe-inline`) → reduziert XSS‑Surface.
   - `style-src`: **realistisch**: `"'self' 'unsafe-inline'"` (mindestens für jetzt), weil:
     - GUSTAV setzt Styles dynamisch in JS (Tooltips/Scroll‑Lock),
     - HTMX injiziert default‑Styles,
     - Inline‑Styles sonst großflächig refactor‑pflichtig wären.
   - Mitigation: `img-src`/`connect-src` bleiben eng (`'self'` + `data:`) → CSS‑Exfil wird stark begrenzt.
2) **H5P `/ajax`:** immer same‑origin erzwingen (Origin oder Referer) und Antworten grundsätzlich `no-store` + `Vary: Origin`.
3) **H5P Student‑Visibility:** Wenn Kurse >100 Sections realistisch sind, bevorzuge **Option B** (dedizierter Learning‑Endpoint), weil sie:
   - false‑denies eliminiert (kein `limit=100` Problem),
   - Payload minimal hält (kein Sections/Tasks Dump),
   - Daten minimiert (keine Liste aller erlaubten IDs → weniger Enumeration/Metadaten),
   - die Logik dort bündelt, wo die “released task” Wahrheit liegt (Learning/DB‑Boundary).
