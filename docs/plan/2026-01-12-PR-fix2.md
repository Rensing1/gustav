### SHOULD FIX (wichtig)
- **F2 [SEC/DOC] `trust proxy` + CSRF Same‑Origin hängt an Proxy‑Invarianten**
  - Kontext: `h5p-service/server.mjs` nutzt `app.set("trust proxy", true)`;
    CSRF‑Checks (`requireSameOrigin`) erwarten korrekte Forwarded‑Header.
  - Evidenz: `h5p-service/server.mjs:707` setzt global `trust proxy=true`;
    `h5p-service/server.mjs:364` baut `expected origin` aus
    `x-forwarded-proto`/`x-forwarded-host`.
  - Impact: Betriebliches Risiko (wenn Proxy‑Header fehlen/falsch sind → legitime
    Requests werden abgewiesen oder Checks sind schwer nachvollziehbar).
  - Nächster Schritt: Dokumentiere die erwarteten Header‑Invarianten
    (Caddy/Reverse Proxy) in einem kurzen Ops‑Abschnitt (z. B. `docs/runbooks/`
    oder `docs/ARCHITECTURE.md`).

- **F3 [SEC/ROBUSTNESS] H5P Sidecar: `trust proxy` enger fassen (nicht global `true`)**
  - Problem: `trust proxy=true` vertraut `X-Forwarded-*` von **jedem** Hop/Caller
    (Defense‑in‑depth wird schwächer, falls der Service jemals ohne
    vorgeschalteten Proxy erreichbar ist).
  - Evidenz: `h5p-service/server.mjs:707` (`app.set("trust proxy", true)`).
  - Impact: Worst‑case Spoofing von Origin/Proto/Host‑Ableitungen (CSRF‑Checks
    werden schwerer belastbar).
  - Nächster Schritt: Setze `trust proxy` auf **single hop** (`1`) oder eine
    explizite Allow‑List (nur Caddy) und sichere das per Source‑Contract‑Test ab.

- **F4 [SEC/BUG] CSRF Same‑Origin: `X-Forwarded-Port` wird nicht berücksichtigt**
  - Kontext: `getPublicOrigin()` (H5P) baut den erwarteten Origin aus
    `X-Forwarded-Proto` + `X-Forwarded-Host` (bzw. `Host`), ignoriert aber
    `X-Forwarded-Port`.
  - Evidenz: `h5p-service/server.mjs:364` nutzt kein `x-forwarded-port`;
    die Web‑App berücksichtigt es (`backend/web/routes/security.py:58`).
  - Impact: False‑negative CSRF‑Rejects bei nicht‑Standard‑Ports / abweichenden
    Proxy‑Setups; Drift zur Python‑Implementierung (`backend/web/routes/security.py`)
    möglich.
  - Nächster Schritt: `X-Forwarded-Port` analog zur Web‑App berücksichtigen
    (inkl. Default‑Port‑Normalisierung) und einen Regression‑Test hinzufügen.

- **F5 [SEC/PRIVACY] `/h5p/healthz`: intern-only oder minimal (keine Infos leaken)**
  - Problem: Healthz ist aktuell un-authenticated (gewollt), aber über den
    Reverse Proxy erreichbar und enthält Diagnosefelder
    (z. B. Storage‑Root/Errors).
  - Evidenz: `h5p-service/server.mjs:720` liefert `storage` im JSON; `storage`
    enthält `root` und bei Fehlern `error` (`h5p-service/server.mjs:428`).
  - Impact: Info‑Leak + unnötige öffentliche Angriffsfläche.
  - Nächster Schritt:
    - Prod‑Setup: `/h5p/healthz` nur intern erreichbar machen
      (Ingress/Caddy IP‑Allowlist oder nicht exponieren; Healthchecks laufen im
      Container/Cluster‑Netz).
    - Zusätzlich: Response auf minimale Felder reduzieren (z. B. nur `status`) und Diagnose nur serverseitig loggen.

- **F6 [BUILD/MAINT] `node_modules` nicht versionieren + Docker Build‑Context schlank halten**
  - Kontext: Prod baut Images via `docker compose ... --build` und hat npm‑Zugriff
    → `npm ci` kann Abhängigkeiten reproduzierbar installieren.
  - Evidenz: Root `.dockerignore` fehlt; `h5p-service/.dockerignore` fehlt
    (Repo‑Snapshot oben).
  - Impact: Ohne `.dockerignore` kann ein lokales `h5p-service/node_modules/` den
    Build‑Context massiv vergrößern (langsame Builds, große Transfers).
  - Nächster Schritt:
    - Lege `.dockerignore` im Repo‑Root an (Build‑Context `.` für `web`/`learning-worker`) **und**
      `h5p-service/.dockerignore` (Build‑Context `./h5p-service`).
    - Mindestens: `**/node_modules/`, `.tmp/`, `tmp/`, `.venv/`, `.pytest_cache/`, `supabase/storage/`.
    - Dokumentiere kurz: “Abhängigkeiten kommen aus `package-lock.json` + `npm ci`”.

- **F7 [TEST/CI] H5P Sidecar Node‑Tests müssen in “Verify” laufen**
  - Problem: Es gibt Node‑Tests unter `h5p-service/test/*`, aber ohne expliziten
    Hook werden sie leicht vergessen (während Python‑Tests grün sind).
  - Evidenz: `h5p-service/test/*` existiert (z. B. `cookies.test.mjs`);

  - Nächster Schritt: Ergänze `make test-h5p` (z. B. `cd h5p-service && npm test`)

- **F8 [CONSISTENCY/FOSS] Third‑Party Notice: Lumi Webcomponents Lizenz ist im Repo nicht referenzierbar**
