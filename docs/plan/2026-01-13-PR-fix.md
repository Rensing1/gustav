## Kontext (wichtig fürs Verständnis)
- Neues Node‑Sidecar `h5p-service/` wird same‑origin unter `/h5p/*` via `reverse-proxy/Caddyfile`
  proxy‑geroutet.
- Schüler laden den H5P Player via `GET /h5p/player/model` (cookie‑auth). Für Schüler gilt:
  **fail‑closed** mit zusätzlichem Access‑Check gegen die Learning API:
  `GET /api/learning/courses/{course_id}/h5p/contents/{content_id}/access` (204/404).
- Teacher Live Detail nutzt den Review‑Player `GET /h5p/player/review` mit signed `review_token`
  (short‑lived Capability Token, HMAC). Im Sidecar wird in Review‑Mode:
  - strikt read‑only erzwungen (nur GET‑Reads, Writes geblockt)
  - `setFinished` aus dem Model entfernt (defense‑in‑depth)
- H5P finishedData wird serverseitig zusätzlich als Learning‑Submission persistiert
  (`learning_submissions(kind='h5p', score_raw/score_max)`) mit Idempotency‑Key.

## Review‑Ergebnis (kurz)
- Kein MUST‑FIX identifiziert; Security‑Design ist insgesamt solide (CSRF same‑origin,
  CSP, fail‑closed Access‑Check, Prod‑Guards, gehärtete SECURITY DEFINER Helpers,
  Performance‑Index für Access‑Check).
- Haupt‑Risiko ist der Umfang (442 Files; viele vendor assets) → Contract‑Tests sind zentral.

## Findings / Follow‑ups (priorisiert)
### SHOULD FIX
1) **OpenAPI: 400‑Responses für H5P model/review Endpoints fehlen**
   - Implementierung gibt 400 `{error: "invalid_request"}` zurück, Spec listet aktuell nur 401/403/404.
   - Risiko: Contract‑Drift, Client‑Fehlerbehandlung uneindeutig.

2) **finishedData → Learning submission forwarding: Failure‑Visibility / Reliability klären**
   - Sidecar antwortet `{success:true}` auch wenn das Forwarding (POST Learning submissions) fehlschlägt.
   - Risiko: Teacher Dashboard zeigt u. U. veralteten Fortschritt ohne eindeutiges Signal.

3) **Licensing: Projektweite Entscheidung zu GPL‑3 vendored H5P Assets dokumentieren**
   - `THIRD_PARTY_NOTICES.md` ist gut, aber es fehlt die “so what” Entscheidung (Repo‑Lizenz/Distribution).

### NICE TO HAVE
- `.dockerignore`: `.env`/`.env.*` aufnehmen (defense‑in‑depth; v. a. bei Remote‑Builders/CI)
- Rate‑Limit/Burst‑Protection für `.h5p` Uploads (DoS surface)
- `h5p-service/server.mjs` in kleine Module splitten (Wartbarkeit)
