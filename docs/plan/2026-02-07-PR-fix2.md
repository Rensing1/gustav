## Priorisierte Findings

### MUST FIX 1: Datei-Material wird im modularen Modul-Fragment nicht inline gerendert
- Befund:
  - Die modulare Fragment-Route rendert Material explizit nur fuer `kind == "markdown"`.
  - Fuer `kind == "file"` fehlt die `FilePreview`-Einbindung; Schueler sehen die Datei dadurch nicht organisch im Modul.
- Belege:
  - `backend/web/main.py:2259`
  - `backend/web/main.py:2266`
  - Vergleich linearer Pfad mit Datei-Vorschau: `backend/web/main.py:1968`
- Risiko:
  - Kern-Use-Case fuer modulare Einheiten ist funktional unvollstaendig.
  - UX-Bruch zwischen linearen und modularen Einheiten.
- Zielzustand:
  - Datei-Material wird im Modul direkt als Inline-Vorschau (oder gleichwertiger Inline-Block) angezeigt.

### SHOULD FIX 1: Legacy-Edge-Delete gibt statischen `Link`-Header statt konkreter Nachfolger-URL aus
- Befund:
  - `Link`-Header enthaelt Platzhalter (`{unit_id}`, `{from_module_id}`, `{to_module_id}`) statt aufgeloester IDs.
- Belege:
  - `backend/web/routes/teaching.py:2510`
  - `backend/web/routes/teaching.py:2531`
- Risiko:
  - Clients koennen den Nachfolge-Endpunkt nicht direkt aus dem Header uebernehmen.
- Zielzustand:
  - `Link`-Header wird pro Request mit realen IDs erzeugt.

### SHOULD FIX 2: Regressionstest fuer Deprecation-/Sunset-/Link-Header fehlt
- Befund:
  - Fuer den Legacy-Delete-Pfad sind die Header nicht als API-Verhaltenstest fixiert.
- Belege:
  - `backend/tests/test_teaching_modular_unit_editor_crud_api_contract.py`
  - `api/openapi.yml:5774`
- Risiko:
  - Spaetere Aenderungen koennen die Deprecation-Semantik still brechen.
- Zielzustand:
  - Expliziter API-Test validiert `Deprecation`, `Sunset` und `Link`.

### SHOULD FIX 3: Datei-URL-Aufloesung im SSR-Pfad oeffnet pro Material eine DB-Verbindung
- Befund:
  - `_resolve_student_material_file_url(...)` verbindet pro Aufruf direkt mit Postgres.
- Belege:
  - `backend/web/main.py:1391`
  - `backend/web/main.py:1434`
- Risiko:
  - Unnoetige Last/Blocking im SSR-Request bei vielen Datei-Materialien.
- Zielzustand:
  - URL-Aufloesung wird gebuendelt oder in einen Repo/API-Pfad verlagert.

### SHOULD FIX 4: OpenAPI dokumentiert Deprecation-Header des Legacy-Edge-Deletes nicht explizit
- Befund:
  - Runtime setzt fuer den deprecated DELETE-Pfad die Header `Deprecation`, `Sunset`, `Link`.
  - Der OpenAPI-Response beschreibt bisher nur `Cache-Control`.
- Belege:
  - `backend/web/routes/teaching.py:2529`
  - `backend/web/routes/teaching.py:2530`
  - `api/openapi.yml:5804`
- Risiko:
  - Client-Generatoren und Integratoren sehen die Migrationssignale nicht vertraglich.
  - Governance-Luecke zwischen Contract und Runtime.
- Zielzustand:
  - `Deprecation`, `Sunset`, `Link` als Response-Header im OpenAPI-Schema dokumentieren.

### SHOULD FIX 5: In-Memory-Fallback kann modulare Units erzeugen, ohne alle Modular-Capabilities sicherzustellen
- Befund:
  - Der In-Memory-Repo-Pfad akzeptiert `unit_type=modular`.
  - Mehrere modulare Endpunkte sind aber capability-guarded und antworten bei fehlenden Methoden mit `503`.
- Belege:
  - `backend/web/routes/teaching.py:245`
  - `backend/web/routes/teaching.py:1178`
- Risiko:
  - Inkonsistentes Verhalten in lokalen/offline Szenarien (Unit-Erstellung erfolgreich, Editor danach nicht nutzbar).
  - Erhoehtes Fehlersuch-Risiko bei "lokal = prod"-Prinzip.
- Zielzustand:
  - Entweder modulare In-Memory-Methoden komplettieren oder `unit_type=modular` im Fallback gezielt blocken.
