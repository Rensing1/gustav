## User Stories und BDD-Szenarien

### Dialogauswertung

Als lernende Person möchte ich, dass eine technisch ungültige KI-Auswertung als Verarbeitungsfehler behandelt wird, damit kein scheinbar gültiges Nullergebnis meine tatsächliche Leistung verfälscht.

- **Gültige Auswertung:** Given die KI liefert für jedes Kriterium einen echten ganzzahligen Score von 0 bis 10 und eine nicht leere Begründung, when der Dialog-Worker die Antwort verarbeitet, then wird die positionsgebundene Kriterienauswertung gespeichert. Automatischer Nachweis: Adapter- und Worker-Tests.
- **Fehlendes Ergebnis:** Given die KI lässt ein Kriterium aus, when der Adapter die Antwort prüft, then entsteht `feedback_invalid_analysis` und kein Nullergebnis. Automatischer Nachweis: Adapter- und Worker-Tests.
- **Falscher Skalartyp:** Given die KI liefert `true`, `"8"` oder `8.0` als Score, when der Adapter die Antwort prüft, then wird sie trotz möglicher Typkonvertierung abgelehnt. Automatischer Nachweis: parametrisierter Adaptertest.
- **Leere Begründung:** Given eine Begründung enthält nur Leerraum, when der Adapter die Antwort prüft, then wird die gesamte Auswertung abgelehnt. Automatischer Nachweis: Adaptertest.
- **Prompt-Drift:** Given der Dialog-Prompt wird im Code geändert, when der Dokumentationsvertragstest läuft, then schlägt er fehl, bis die kanonische Referenz dieselbe Fassung enthält. Automatischer Nachweis: Prompt-Drift-Test.

### H5P-Aufgabenwechsel

Als lernende Person möchte ich beim Wechsel zwischen zwei H5P-Aufgaben sofort den Inhalt der gewählten Aufgabe sehen, damit ich nicht versehentlich im vorherigen Inhalt weiterarbeite oder dessen verspätete Rückmeldung erhalte.

- **Andere Aufgabe:** Given eine angemeldete lernende Person hat zwei zugängliche H5P-Aufgaben, when sie innerhalb derselben montierten Lernansicht von Aufgabe A zu Aufgabe B wechselt, then wird der alte Player entfernt und Aufgabe B mit ihrer eigenen Content- und Context-ID angezeigt. Automatischer Nachweis: `@feature-acceptance` in `h5p-learner-feedback-progress.spec.ts` sowie Komponententest.
- **Identische Aufgabe:** Given lediglich nicht identitätsbildende Daten werden aktualisiert, when die Aufgabenkarte neu gerendert wird, then bleibt derselbe Player erhalten. Automatischer Nachweis: Komponententest.
- **Verspätete Antwort:** Given der alte Player wartet noch auf eine Ergebnisantwort, when vorher zu Aufgabe B gewechselt wird, then darf diese Antwort keine sichtbare Rückmeldung mehr auslösen. Automatischer Nachweis: Komponententest.
- **Entzogene Mitgliedschaft:** Given die Kursmitgliedschaft wird entzogen, when das Player-Modell erneut angefragt wird, then bleibt der Zugriff privat und wird verweigert. Automatischer Nachweis: bestehender authentifizierter Browsertest.
